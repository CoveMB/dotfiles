# Capability and preservation gates

This file states the qualification contract. Machine-local results, exact source
revisions, file hashes, provider observations and recovery paths belong in the
owner-only run state. Unexercised capabilities remain pending.

| Capability | Canonical owner | Required evidence before acceptance |
| --- | --- | --- |
| Instructions | `codex/AGENTS.md` | Independent generated regular files, lossless reconstruction, each complete rule below 24,000 bytes, native aggregate budget and beginning/middle/tail behavior; no duplicate global route |
| Nested rules | Host adapter | Explicit inspection before descendant work; root/nested fixtures; no AGENTS.override/fallback parity claim |
| Role bodies | `codex/agents/*.toml` | Four generated prompts; actual native tool IDs; source identity and workspace collision check before dispatch |
| Read-only children | Native tool restrictions | No edit/shell/delegation/browser/write-capable MCP route; negative fixture probes and two independent fresh-context returns; disable if ineffective |
| Implementation child | Native sandbox and bounded approvals | Approved disposable edit/test, no child launch; no unsandboxed fallback |
| Context7 | Existing shared skill and separate native MCP | Credential-free registration, two-tool exposure, real public resolve/query; effective connected path verified |
| Accessibility (4) | Canonical portable exporter | Complete exported policies/resources; dictation/reading/prose/mixed routing checks |
| Research (29) | Full portable package | Complete sibling/shared resources; representative orchestrator/resource routing; external Google/Zotero conditional |
| Humanizer (3) | Complete reviewed sibling skills | Preserve editorial/faithful/plain-language distinctions and confidentiality rules |
| Material Review (2) | Trusted canonical bundles | Trusted-workspace evaluation only; retain both simplification gates and independent scopes |
| Incremental Plans (2) | Canonical host contract | App support pending until actual invocation/coordination passes; separate Antigravity export, no edits to the other hosts' installed sources |
| Cleanup (1), Ponytail (6), Ultra/Mega | Explicit-only policies | Inert native metadata probe first; inspect real catalog policy; no mode/cleanup/compression activation as a smoke test |
| Caveman/Superpowers | Complete skills-only resources and adapter | Existing role/model restrictions; no bootstrap hooks, forced models or browser companion; native operations or explicit manual fallback |
| Personal helpers (2) | Complete isolated personal bundles | Resource access; Obsidian rendering and GitHub external writes remain separate acceptance |
| Compression | Exact requested backend workflow | Separately deferred; exact input/provider/transmission/output approval |
| Recursive mode and Codex runtime integrations | Existing Codex owners | Deferred; no bootstrap or connector/auth migration |
| Existing hosts | Current settings/source fingerprints and regression tests | Codex settings, instruction targets, role sources, plugin registrations and OpenCode live settings preserved; extraction preserves all pre-existing changes |

Only passing candidates may enter global discovery. An unavailable model, ignored
explicit-only flag, unresolved source collision or unenforceable role boundary
leaves the affected capability disabled. Default sandboxing stays enabled; retain
saved grants as data while reviewed Ask/Deny rules change effective behavior.
Do not claim a host-enforced concurrency limit without observing one.

The native tool inventory can differ from documentation examples. Never feed an
unverified identifier into a child allowlist: the host may hang on unmapped names.
MCP inheritance and mandatory messaging need explicit inspection, including
indirect mutation routes. A prompt saying “read-only” is insufficient.
